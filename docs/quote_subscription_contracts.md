## 계약 1. 캐시 키 단위

**핵심 규칙: 종목코드 단위 공유 캐시는 통합(UNIFIED) 시세 전용이다.**

거래소(KRX/NXT)를 지정한 시세는 종목코드만으로 키를 잡으면 통합 값과 충돌한다.
실제로 `#858`(NXT 현재가가 종목코드 키 KRX 캐시로 제공)·`#871`(통합 틱이 KRX 표시값과
종목코드 단위 캐시를 덮어씀)이 이 축에서 났다.

| 저장소 | 키 | 담는 값 |
| --- | --- | --- |
| `stock_price_repository` 현재가 캐시 | **종목코드만** | 통합(`H0UNCNT0`) 기준 값 **전용** |
| `price_stream_service` SSE 큐 | **(종목코드, 거래소)** | 거래소 지정 틱(KRX/NXT) 포함 |
| `execution_flow_service` 스냅샷 캐시 | **(종목코드, 거래소)** | 체결강도·수급 스냅샷 |

현재 코드가 이 계약을 지키는 방식:

- `price_stream_service._handle_tick`: 거래소 지정 틱(`_exchange != 'UN'`)은 **화면 표시 전용**으로
  취급해 공유 캐시·저장소를 건드리지 않고 같은 거래소 SSE 큐로만 fanout 한 뒤 반환한다.
- `stock_query_service.get_current_price`: `exchange != Exchange.KRX`이면 캐시·스트림 경로를
  **우회**한다(`exchange_specific_bypass` 카운터로 계측).

**추가 시 규칙**

- 거래소·시장·통화처럼 같은 종목코드에 여러 값이 존재할 수 있는 축을 새로 도입하면,
  **공유 캐시에 넣지 말고 키에 그 축을 포함한 별도 저장소를 쓴다.**
- 공유 캐시를 쓰는 새 경로는 자기가 통합 기준 값만 다루는지 확인한다. 아니면 우회한다.
- 우회 경로는 계측을 남긴다(어떤 경로가 캐시를 못 쓰는지 드러나야 한다).

## 계약 2. 시세 갱신 주체와 폴백 체인

**핵심 규칙: 폴백 단계는 "응답이 성공했는가"가 아니라 "값이 실제로 찼는가"로 판정한다.
그리고 단계 순서는 장 운영 여부에 따라 바뀐다.**

`#897`(폴백 신선도 검증)·`#902`(장외 등락률 기준 통일)가 이 축에서 났다.

### 2-1. 단계 순서 — 장 운영 여부에 종속

`FavoriteService.get_with_details` 기준:

| 상태 | 순서 |
| --- | --- |
| 장중 | StockQueryService(신선 WebSocket 스냅샷 우선, REST fallback) → 메모리 캐시 → DB 일봉 스냅샷 |
| 장외 | **DB 일봉 스냅샷(최근 거래일)** → StockQueryService → 메모리 캐시 |

장외에 일봉을 먼저 두는 이유: KIS 현재가 API 는 장 시작 전·비거래일에 **전일 종가를 현재가로,
등락률은 `0.00`** 으로 돌려준다. 라이브 값을 그대로 쓰면 같은 표에 `0.00%`(API 경로)와
`+4.03%`(DB 경로)가 섞여 어느 쪽이 맞는지 알 수 없게 된다.

### 2-2. 완료 판정 — `rt_cd == "0"` 은 충분조건이 아니다

`_apply_price_rate` 가 세 상태를 구분한다:

| 받은 값 | 반영 | 다음 단계로 | 이유 |
| --- | --- | --- | --- |
| 현재가 없음 | 안 함 | **간다** | 응답이 성공이어도 빈 값이면 해결된 것이 아니다 |
| 현재가만 있음 (등락률 없음) | 값은 남김 | **간다** | 불완전 소스(WebSocket 틱 등). 완전한 소스를 찾으면 통째로 덮어쓴다 |
| 현재가 + 등락률 | 반영 | 멈춤 | 완료 |

`#897` 이전에는 첫 줄이 "빈 값으로 고정되고 이후 단계를 타지 않아" 화면에 `-` 만 남았다.

**추가 시 규칙**

- 새 폴백 단계를 끼울 때 **성공 응답과 완전한 값을 구분**한다. `rt_cd`만 보면 안 된다.
- 부분 값만 주는 소스(틱 등)는 값을 남기되 **미완료로 보고**해 뒤 단계가 덮어쓸 수 있게 한다.
- **기준일이 섞이지 않게 한다.** 같은 표에 들어가는 값들은 같은 세션 기준이어야 한다.
  장 운영 여부에 따라 순서를 바꿔야 하는지 반드시 확인한다.
- 종목당 timeout 을 걸어 한 종목이 전체 조회를 막지 않게 한다(현재 query 5초, minervini 3초).

## 계약 3. 슬롯 회계

**핵심 규칙: 진실 소스는 브로커 원장이다. 정책 내부 장부는 폴백이다.**

KIS 웹소켓 한도는 `MAX_WS_SLOTS = 40`, Price 1슬롯 · PT(프로그램매매) 1슬롯이다.
`#906`~`#910`(수동 PT 구독 보존·슬롯 선점·가격 동반 구독)이 이 축에서 났다.

### 3-1. 사용 슬롯 계산

`SubscriptionPolicy._calculate_used_slots`:

1. `_get_broker_ledger()` 가 KIS 실제 등록 원장을 주면 **그 `total` 을 그대로 쓴다.**
   내부 장부(`_active_codes_*`)는 재연결·직접 구독 경로에서 실제 등록과 어긋날 수 있다.
2. 원장이 없으면 `_external_reserved_slots + len(price) + len(pt)`.

`_rebalance` 의 예약 슬롯 계산도 같은 원칙이다 — 원장이 있으면
`total - price_codes - program_trading_codes` 로 **정책이 소유하지 않는 등록**
(장운영정보·체결통보 등)을 예약분으로 잡고, 없으면 `_external_reserved_slots` 를 쓴다.

### 3-2. 우선순위와 선점

| 우선순위 | 값 | 용도 | 선점 |
| --- | --- | --- | --- |
| `CRITICAL` | 0 | 프로그램매매 | **절대 밀려나지 않음**. 슬롯 부족 시 요청 자체를 거절(False 반환) |
| `HIGH` | 1 | 포트폴리오 / 관심종목 알림 | 밀어내기 가능 |
| `MEDIUM` | 2 | 전략 워치리스트 / 프리미엄 | 밀어내기 가능 |
| `LOW` | 3 | UI 화면 조회 | 가장 먼저 밀려남 |

`_rebalance` 는 종목별 **최선 우선순위**(`min`)로 정렬해 greedy 배정한다. 한 종목이 여러
카테고리에서 요청되면 가장 높은 우선순위를 따른다.

`CRITICAL` 이 밀어내기 대신 **거절**을 택하는 이유: 프로그램매매 구독을 조용히 밀어내면
그 전략이 신호를 못 받는 것을 아무도 모른다. 거절은 로그에 남는다.

### 3-3. 정책 밖 구독

**슬롯을 쓰지만 `SubscriptionPolicy` 계산에 안 잡히는 구독이 있다.** 이들은
`set_external_reserved_slots` 로 예약분에 반영해야 한다(현재 호출처: `websocket_watchdog_task`).

- 장운영정보·체결통보 등 정책이 소유하지 않는 등록
- **거래소 지정 구독(KRX/NXT 탭)** — 화면을 열어둔 동안 1슬롯을 추가로 쓴다. todo `M-8` 의
  실계좌 확인 항목이며, 슬롯 계산 밖이라는 점이 이 문서 기준으로도 예외다.

**추가 시 규칙**

- 새 구독 경로는 **슬롯 계산에 포함되는지** 먼저 정한다. 포함 안 되면
  `set_external_reserved_slots` 로 예약분에 넣는다. 둘 다 안 하면 한도를 조용히 넘긴다.
- 해지·재연결·재시작 경로에서 슬롯이 회수되는지 확인한다. 회수 안 되면 앱 재시작 전까지
  슬롯이 물린다(M-8 의 SSE 종료 엣지 케이스가 이 형태다).
- 새 우선순위를 만들지 말고 기존 4단계에 맞춘다. 밀어내기 불가 요구가 있으면 `CRITICAL`
  처럼 **거절**로 설계한다 — 조용한 강등은 진단이 불가능하다.

## 가드 테스트 (2026-08-30 신설)

`tests/unit_test/services/test_quote_subscription_contract_guard.py` 가 위 체크리스트를
신규 경로 추가 시 실제로 밟게 하는 배선이다. 고정 대상:

| 계약 | 고정한 것 |
| --- | --- |
| 1 | 공유 현재가 캐시 쓰기 모듈 allowlist · 거래소 지정 틱 조기 반환이 공유 저장소 쓰기보다 앞인지 |
| 2 | 장중/장외 폴백 단계 순서 · 모든 `_fill_from_*` 가 `_apply_price_rate` 를 거치는지 · 3상태 |
| 3 | `MAX_WS_SLOTS`·우선순위 4단계 · 정책 밖 직접 구독 allowlist · `set_external_reserved_slots` 호출처 · 원장 우선 |
| — | 이 문서의 '관련 테스트' 표가 실재하는 파일을 가리키는지 |

**실패는 "코드가 틀렸다" 가 아니라 "계약을 확인하고 목록을 갱신하라" 는 뜻이다.**
실패 메시지에 계약 요지와 이 문서 경로가 함께 실린다.

가드의 주된 실패 모드는 *아무것도 안 잡는 가드*라, detector 를 합성 위반 소스로 검증하는
케이스를 같은 파일에 넣었다. 도입 시에도 실제 코드를 일시 변형해(새 캐시 쓰기 1건 ·
장외 폴백 순서 뒤집기 1건) 가드가 실제로 실패하는 것을 확인한 뒤 원복했다.
